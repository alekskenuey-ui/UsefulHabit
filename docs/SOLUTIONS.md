# Варіанти вирішення для кожної проблеми аудиту

Позначки: ⭐ — моя рекомендація. Складність: 🟢 мала / 🟡 середня / 🔴 велика.

---
## C1. Немає окремих URL (мови, політика, умови)
| Варіант | Суть | Плюси | Мінуси |
|---|---|---|---|
| A | Свій простий генератор (Node-скрипт): із `src/locales` і `src/legal` створює `/{lang}/index.html`, `/privacy/`, `/terms/`, sitemap, hreflang | 🟡; без фреймворку, легко підтримувати | Потрібно самому розвивати генератор |
| B ⭐ | Astro (статичний фреймворк) з i18n і колекціями для оглядів/оферів | 🟡; зручно додавати огляди, країни, landing pages; швидкий сайт | Нова залежність, потрібне навчання на старті |
| C | Лишити один файл, додати окремі HTML лише для політики й умов | 🟢; найшвидше | Мови без URL, hreflang неможливий, масштабування слабке |

Рекомендація: B (або A, якщо хочете мінімум технологій). Хостинг: Cloudflare Pages / Netlify підключаються до GitHub і публікують автоматично.

## C2. Сайт обіцяє «огляди та порівняння», а їх немає
| Варіант | Суть | Мінуси |
|---|---|---|
| A | Написати 3–5 перших реальних оглядів за шаблоном (за даними виробників, які ви надасте) до запуску реклами | Потрібні конкретні продукти та джерела |
| B ⭐ | Тимчасово змінити формулювання на те, що є: «Гіди з читання складу та етикетки», опублікувати 3–5 освітніх гідів (реальний контент), огляди додати згодом | Менш «комерційна» подача на старті |
| C | Запустити рекламу лише на освітні гіди, огляди пізніше | Повільніше монетизація |

Рекомендація: B одразу, потім A.

## C3. Немає даних власника
| Варіант | Суть |
|---|---|
| A ⭐ | Додати назву ФОП/ТОВ, адресу, контакти у футер і політики |
| B | Якщо юрособи ще немає, спершу оформити її (для UA — ФОП; питання оподаткування — до бухгалтера) |
| C | Для ЄС додатково призначити представника за ст. 27 GDPR (послуга за плату) |
Без цього Google може вимагати верифікацію рекламодавця, а політики GDPR слабкі.

## C4. Немає cookie-згоди
| Варіант | Суть | Складність |
|---|---|---|
| A ⭐ | Готовий CMP із підтримкою Google Consent Mode v2 (наприклад Cookiebot, CookieYes) | 🟢; платний/безкоштовний план |
| B | Власний банер + шаблон Consent Mode в GTM | 🔴; більше ризиків помилок |
| C | Спершу запуститись без нестрого необхідних cookie (без GA4/Pixel), вимірювати кліки на стороні партнерки/трекера | 🟢; швидко, але менше даних для оптимізації реклами |

## H1. Заяви про процес як про наявний
A ⭐ Переписати як «редакційний стандарт, за яким будуть готуватись матеріали» і повернути теперішній час після перших оглядів. B Прибрати блок до публікації матеріалів. C Лишити, якщо перші огляди вже опубліковано.

## H2. Вага 540 КБ
A ⭐ Окремі файли за мовами (вирішується разом із C1). B Лого в SVG/WebP (економія ~120 КБ). C Відкладене завантаження декоративних іконок.

## H3. Шрифти
A ⭐ Self-host (Fraunces, Manrope + Noto для TH/AR/UR/KA/HY): швидше і без передачі IP до Google (у ЄС є судова практика проти вбудованих Google Fonts). B Системні шрифти для нелатинських мов. C Лишити Google Fonts із `font-display: swap`.

## H4. Переклади без вичитки
A ⭐ Вичитка носіями для пріоритетних 6–8 ГЕО (фрилансери/агентство). B Перевірка всіх мов, але лише тексти, що стосуються здоров'я та реклами. C Запуск реклами спочатку лише в країнах, де мова перевірена.

## H5. Юридичні тексти не звірені
A ⭐ Юрист по ЄС (один, GDPR) + окремо для UA; решту ГЕО запускати пізніше. B Я перевіряю кожне ГЕО за офіційними джерелами (закони, регулятори), юрист робить фінальний огляд. C Використати стандартні форми регуляторів, адаптувавши до фактичної діяльності.

## H6. Немає аналітики
A ⭐ GTM + GA4 + Meta Pixel, завантаження після згоди (CMP). B Server-side GTM + Conversions API пізніше (для точнішого трекінгу). C Cookieless-аналітика (Plausible/Umami) + лише Google Ads конверсія. Потрібні реальні ID.

## H7. Партнерські посилання
| Варіант | Суть |
|---|---|
| A ⭐ | Реєстр `offers.json` + прозорий перехід `/go/{offer}` з UTM/click ID, `rel="sponsored"`, подія `click_affiliate`, розкриття перед CTA |
| B | Прямі посилання з data-атрибутами (простіше, менше контролю) |
| C | Зовнішній трекер (Keitaro/Binom/RedTrack) як проксі кліків |
Незалежно від варіанту: жодного маскування переходів під інформаційні, без клоакінгу.

## M1. Два H1
A ⭐ Вирішується статичними сторінками (один H1 на URL). B Тимчасово прибрати прихований H1.

## M2. SEO-файли
A ⭐ Генератор створює sitemap.xml, robots.txt, canonical, hreflang, og:image, breadcrumbs. B Додати вручну лише для головних мов.

## M3. Окремі сторінки Contact, Cookie Policy, Affiliate Disclosure, Medical Disclaimer
A ⭐ Окремі короткі сторінки (використовуємо наявні тексти). B Об'єднати в одну «Legal hub» з якорями.

## M4. Фоновий декор
A ⭐ Залишити на desktop, скоротити кількість на мобільних. B Замінити на один статичний SVG-фон. C Прибрати анімацію на мобільних.

## M5. Посилання на політику з форми
Вирішується разом із C1 (посилання на реальні URL).

## L1. Фавікон / L2. 404
Фавікон із логотипу (SVG + PNG 32/180/512). 404-сторінка кожною мовою.
